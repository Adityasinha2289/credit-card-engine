# Phase 10: AI Systems & Logic Engines

RenoCred employs a tiered approach to "Intelligence", combining deterministic Rule Engines with generative AI.

## 1. Deterministic Rule Engines
These are pure functions running client-side. They process raw arrays (transactions, cards) and return structured insights. They are fast, zero-cost, and predictable.

### A. The Behaviour Engine (`features/behaviour`)
*   **Input**: `Transaction[]`
*   **Logic**: Aggregates spend by category and checks thresholds.
*   *Example Rule*: "If `dining` spend > 15% of total, return an 'Increase' insight with an impact score of 78."

### B. The Recommendation Engine (`features/recommendation`)
*   **Input**: `User Profile (Primary Goal)`, `Top Spending Categories`, `Available Cards (Knowledge Graph)`
*   **Logic**: Maps the user's highest spending category (e.g., Travel) to the card in the database with the highest multiplier for that category (e.g., HDFC Infinia).
*   **Output**: A structured `CardRecommendation` object.

### C. The Financial Health Engine (`features/financial-health`)
*   **Input**: `Credit Score`, `Credit Utilization`, `Salary`
*   **Logic**: Uses a weighted formula to generate a RenoCred Score. Maps the raw score to a Grade (A+, A, B, C, D).

## 2. Generative AI (Taqdeer)
Taqdeer is the conversational agent providing complex financial advice.

### The Pipeline (`features/taqdeer`)
1.  **Intent Classification (Local)**: When a user types a prompt, Taqdeer checks a local registry (e.g., `features/knowledge/intentRegistry.ts`). If the user asks "What is my credit score?", Taqdeer catches this regex intent, bypasses the LLM entirely, and returns the hardcoded value from the store.
2.  **Prompt Construction**: If the intent is unknown, Taqdeer generates a massive system prompt. It stringifies the user's active cards, current balances, and top 3 spending categories into a context block.
3.  **LLM Call**: It hits the Gemini API (`/api/health-ai` proxy).
4.  **Structured Output**: The LLM is instructed (via prompt engineering) to return Markdown, including specific button syntaxes (e.g., `[ACTION:Simulate CIBIL]`) which the UI parser then converts into interactive React components.

## Integration with UI
*   Insights generated by the Rule Engines are picked up by the **Notification Engine**, which scores them by priority. The highest priority insight is rendered in the `HomeTab` as the "Top Action".
*   This creates the illusion of a single, omniscient AI, when in reality, it is 4 distinct engines pushing data to a priority queue.
